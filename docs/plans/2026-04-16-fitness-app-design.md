# 健身日志安卓 App 设计文档

## 1. 产品定位

这是一个 `自用优先、实用优先` 的安卓健身记录 App，目标是在首版先解决三个核心问题：

1. 方便记录每天的健身内容
2. 可以设置并追踪明确的健身目标
3. 能看到有行动价值的基础统计结果

产品策略采用 `渐进式 MVP`。首版不追求功能大而全，而是优先保证离线可用、录入顺手、数据不容易丢，先做成一个每天愿意打开使用的工具。

---

## 2. 目标用户与使用场景

### 目标用户

- 当前核心用户就是你自己
- 健身习惯是 `混合型`，既有力量训练，也有有氧训练
- 偏好 `结构化详细记录`，希望把训练内容记录得足够完整，方便后续复盘与统计

### 典型使用场景

1. 训练结束后，记录一次完整的力量训练
2. 跑步、骑行、跳绳后，记录有氧数据
3. 每天或隔天记录体重、体脂、疲劳感等身体状态
4. 定期查看训练频率、体重变化、动作 PR、有氧累计情况
5. 设定体重目标、频率目标、表现目标，并查看当前进度

---

## 3. 产品目标

### 首版目标

- 支持混合型健身记录
- 让详细记录过程尽量顺手
- 支持目标设置和基础进度追踪
- 提供最有价值的基础统计
- 所有核心功能离线可用

### 非目标

以下功能明确不进入首版：

- 社交互动
- 饮食热量库
- 课程或社区内容
- 云同步
- 多设备同步
- 穿戴设备接入
- 复杂 AI 分析

---

## 4. 产品结构

首版建议采用 `三模块平衡型` 设计，围绕 `记录`、`目标`、`统计` 三个核心能力展开，并补充一个设置入口。

### 页面结构

1. 首页
2. 记录页
3. 目标页
4. 统计页
5. 我的 / 设置页

### 信息架构思路

- 首页负责展示今天状态和快速入口
- 记录页负责录入和编辑训练数据
- 目标页负责设置与追踪目标
- 统计页负责展示趋势和阶段成果
- 设置页负责提醒、单位、导出等辅助功能

---

## 5. MVP 必做功能

### 5.1 首页

- 展示今天日期
- 展示今天是否已记录训练
- 展示今天是否已记录体重
- 展示本周训练次数
- 提供快速新增入口

### 5.2 力量训练记录

- 新增一次力量训练
- 一次训练中支持多个动作
- 每个动作支持多组记录
- 每组记录字段：
  - 重量
  - 次数
  - 备注（可选）
- 动作级字段：
  - 动作名称
  - 备注（可选）

### 5.3 有氧训练记录

- 新增一条有氧训练记录
- 字段包括：
  - 项目
  - 时长
  - 距离
  - 配速或平均心率
  - 备注

### 5.4 身体状态记录

- 记录体重
- 可选记录：
  - 体脂
  - 围度
  - 睡眠时长
  - 疲劳感
  - 备注

### 5.5 历史查看与编辑

- 按日期查看历史日志
- 查看某天的训练详情
- 修改过去的力量、有氧、身体状态记录

### 5.6 常用项目复用

- 保存常用动作模板
- 新增动作时支持快速选择常用动作
- 新增组时自动带出上一组数据，减少重复输入

### 5.7 目标管理

首版只做 3 类目标：

1. 体重目标
2. 每周训练次数目标
3. 表现目标

表现目标的例子：

- 卧推达到某个重量
- 深蹲达到某个重量
- 5km 跑进某个时间

### 5.8 基础进度展示

每个目标展示：

- 当前值
- 目标值
- 截止日期
- 进度条

### 5.9 基础统计

首版统计只做最有行动价值的结果：

- 每周训练次数
- 总训练时长
- 体重趋势
- 常用动作 PR 或最高记录
- 有氧总距离 / 总时长

### 5.10 本地存储与导出

- 所有数据本地离线可用
- 支持本地导出备份

## 6. 页面设计建议

### 6.1 首页

建议内容：

- 今日日期
- 今日状态卡片
- 本周训练次数
- 最近一次训练摘要
- 快速新增按钮

首页要解决的问题不是展示复杂数据，而是让你一打开就知道：

- 今天有没有记
- 现在该不该补记录
- 从哪里最快开始记录

### 6.2 记录页

建议拆成三个录入入口：

1. 新增力量训练
2. 新增有氧训练
3. 记录身体状态

力量训练录入结构建议：

`训练 -> 动作 -> 组`

例如：

- 胸部训练
  - 卧推
    - 60kg x 8
    - 60kg x 7
  - 上斜卧推
    - 22.5kg x 10

这样后续做动作趋势、训练量统计、PR 统计都会更自然。

### 6.3 目标页

每个目标包含：

- 目标类型
- 开始值
- 当前值
- 目标值
- 截止日期
- 备注

目标页不需要做得很复杂，首版重点是让目标进度能被看见。

### 6.4 统计页

建议首版做 4 类卡片：

1. 训练频率
2. 体重趋势
3. 力量表现
4. 有氧累计

统计页要解决的是“看完后知道接下来该怎么练”，而不是只是把数据堆出来。

### 6.5 设置页

首版设置页只保留基础功能：

- 单位设置
- 默认常用项目
- 提醒设置
- 数据导出

### 7.4 有氧记录

- 项目
- 时长
- 距离
- 配速
- 平均心率
- 卡路里（可选）

### 7.5 身体状态记录

字段建议：

- id
- 日期
- 体重
- 体脂
- 围度
- 睡眠时长
- 疲劳感
- 备注

### 7.6 目标

字段建议：

- id

- 开始值
- 当前值
- 目标值

## 8. 关键交互原则

### 8.1 详细记录但减少重复输入

虽然你偏好结构化详细记录，但录入过程仍然要尽量快。建议通过以下方式优化：

- 常用动作快速复用
- 自动带出上一组数据
- 常见有氧项目快速选择
- 身体状态字段默认只展开高频字段

### 8.2 支持先保存再补充

训练结束后并不一定有耐心一次填完所有字段，所以需要支持：

- 先快速保存
- 稍后继续编辑补充

### 8.3 历史可编辑

实际使用中，经常会补记、改记，因此历史编辑不是附加功能，而是首版必须保证顺手的能力。

## 9. 技术方案建议

首版推荐技术栈：

- Kotlin
- Jetpack Compose
- Room
- Navigation Compose
- ViewModel

### 技术选择原因

- `Jetpack Compose` 适合快速构建表单、列表和卡片式页面
- `Room` 适合本地结构化数据存储和查询
- `ViewModel` 能稳定承载页面录入状态，避免页面切换或配置变化导致数据丢失
- `Navigation Compose` 足够支撑首版页面跳转

### 架构建议

首版建议走轻分层：

- `data`
- `domain`
- `ui`

在一个 App 工程内按目录分层即可，不必一开始拆过多 Gradle module。

## 11. 推荐开发顺序

### 阶段 1：底座

- 创建安卓项目
- 配置 Compose、Room、Navigation
- 建立基础主题和页面骨架
- 创建数据库和基础实体

### 阶段 2：打通核心记录链路

- 完成首页
- 完成力量训练录入
- 完成历史查看与编辑

### 阶段 3：补全混合型记录

- 完成有氧记录
- 完成身体状态记录

### 阶段 4：增加目标与统计

- 完成目标页
- 完成统计页

### 阶段 5：增强体验

- 动作模板
- 提醒功能
- 导出备份

## 12. 原型设计优先顺序

建议先画以下 3 张原型：

1. 首页
2. 新增力量训练页
3. 历史详情 / 编辑页

这三个页面一旦跑通，App 就已经可以开始使用。

第二批原型再画：

1. 新增有氧训练页
2. 身体状态记录页
3. 目标页
4. 统计页

---

## 13. 成功标准

如果首版做完后满足以下条件，就说明 MVP 是成功的：

- 你能在 1 到 2 分钟内完成一次完整训练记录
- 你愿意连续使用至少两周
- 你能从统计页快速看到体重和训练变化
- 你会主动查看目标页确认当前进度
- 你不担心离线或数据丢失问题

---

## 14. 后续扩展方向

当首版稳定后，可以按优先级考虑以下扩展：

1. 云备份或网盘备份
2. 多设备同步
3. 更丰富的图表分析
4. 周报 / 月报
5. 健康平台接入
6. 更完整的训练计划系统

---

## 15. 结论

这款 App 的正确起点不是“做一个很全的健身平台”，而是先做一个你自己每天愿意打开的记录工具。

围绕 `记录`、`目标`、`统计` 三个核心模块，以 `离线可用、结构清晰、录入顺手` 为首版原则，是当前最适合的方向。
